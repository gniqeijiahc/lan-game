# 小游戏厅（Trystero 联机）

纯静态网页，托管在 GitHub Pages，不需要自己的服务器。

## 怎么玩

1. 打开首页，输入昵称和 **4 位房间号**（或扫房主分享的二维码）。
2. **第一个进入房间的人是房主**，由房主选择游戏；之后进入的是客人，只能跟着进入房主选的游戏。
3. 房间最多 10 人。双人游戏由房主和下一位进入的人上场，其余的人**观战**；多人游戏（如 🎨 你画我猜，2–10 人）所有人一起玩，**中途也能加入**。
4. 玩家离开时，观战者按进入顺序补位；**房主离开时，名单里的下一位自动接任房主**。
5. 房主点"结束游戏"，所有人回到大厅，可以换下一个游戏。

## 工作原理

- 大厅连一次房间，游戏放在 `<iframe>` 里运行，换游戏不会掉线。
- 游戏里的联机消息由大厅转发（`shared/embed.js` 让游戏以为自己在直接用 Trystero），所以每个游戏页面不用关心房间、房主、观战。
- 观战画面：房间里有观战者时，第一位玩家的页面会定时把自己的画面拍成快照，发给观战者（只读，不可操作）。
- 房主判定没有服务器：加入后先等约 3 秒看有没有现成名单，没有就自己当房主；同时进入时按进入时间排序；出现两个房主时人数多的一方胜出。

## 目录结构

```
index.html            大厅（输入房间号、选游戏）
shared/
  hub.js              大厅界面、游戏内嵌与观战
  room.js             房间网络层（房间号、房主、名单、接任）
  embed.js            游戏被内嵌时的联机转接 + 观战快照
  lobby.js            单页模式的联机模块（游戏独立打开时使用）
  style.css           共用样式
games/
  registry.js         游戏清单（新增游戏在这里登记）
  rps/ connect-four/ draw/ quoridor/   各个游戏
  secret-word/        多人同猜（Jina 向量相似度，房主出题并代算）：index.html 页面、words.js 词库、config.js 接口设置、logic.js 计分逻辑
```

## 新增一个游戏

给开发者（或 AI）的完整规范见 `GAME_SPEC.md`。简要步骤：

1. 在 `games/<id>/index.html` 写游戏，用 `shared/lobby.js` 的 `createLobby` 联机（参考 `games/rps/`）。
2. 在 `games/registry.js` 加一项，写明 `min` / `max` 人数。
3. 游戏既能独立打开调试（页面自带二维码），也会被大厅内嵌运行，不用写两套。

## 🔮 秘密词（多人同猜）

每次进入游戏，从 `words.js` 随机抽一个 4–8 字的词语；房间里**所有人一起猜同一个词**，共用一份猜测记录。页面用 **Jina embeddings** 算出"猜的词"和"秘密词"的语义相似度，换算成百分比（开局时拿 24 个无关词校准，使"随便一个词"约等于 0%）。

- **房主就是主机**：只有房主的页面持有秘密词，并负责向 Jina（经 Worker）发请求。每个人（含房主）猜的词都发给房主去算，房主把整局的公共状态（字数、提示、所有人的猜测和百分比）广播给大家；所有人都**不需要 Key**。秘密词在猜出来或放弃之前不会离开房主的页面。
- **规则**：谁猜对谁赢，结果里会点名；"类别 / 揭示一个字"提示所有人都能用、全员共用；"放弃"和"再来一局"只有房主能点。中途加入的人会立刻同步到当前进度；房主离开后下一位房主接任，并开新的一局。
- **防滥用**：每人同时只能排一个词，同一人至少间隔 0.5 秒，一局最多记录 120 次猜测，用来保护房主的 API 额度。
- **API Key**：不要写进仓库（GitHub Pages 是公开的，写进去等于公开送人）。Jina Key 存在 Cloudflare Worker 的 Secret（名称 `JINA_API_KEY`）里，页面完全看不到。
- **共用模块的改动**：为了让游戏知道谁是房主，`shared/hub.js` 在发给游戏页面的 `init` / `peers` 消息里多带了一个可选字段 `host`（房主的 peerId），`shared/embed.js` 把它放到 `room.host`。其他游戏不读它，不受影响。直接打开游戏页面（没有大厅）时没有房主，退而求其次用"id 最小的人"当主机。
- **Cloudflare Worker 代理**：代码在 `cloudflare/jina-proxy.js`，部署在 `https://jina-proxy.chaijieqing2718.workers.dev/`（`config.js` 的 `API_URL` 指向它）。它只接受来自 `https://gniqeijiahc.github.io` 的请求、只允许指定模型、限制每次的词数和长度；要改来源白名单或模型，改这个文件后到 Cloudflare 控制台 Workers & Pages → 该 Worker → Edit Code 重新粘贴并 Deploy。想改回直连 Jina，把 `API_URL` 换回 `https://api.jina.ai/v1/embeddings`，房主就要在页面里自己填 Key。
- 模型、校准词数量、百分比曲线都在 `config.js`；加词只需编辑 `words.js`（4–8 个汉字）。
- **防作弊**：秘密词只在房主页面的内存里，其他玩家拿不到；但房主自己打开开发者工具能看到答案，词库 `words.js` 也是公开的。要彻底防作弊，需要等有后端（Worker）之后把选词放到服务端。

## 连不上时

默认用 Nostr 做信令。可在网址 `?` 后加参数换通道（房间号仍在 `#` 后面）：

- `?s=torrent`
- `?s=mqtt`

**同一个房间的所有人必须用同一个通道。** 手机流量（运营商 NAT）或严格路由器下可能打洞失败，这是 WebRTC 的限制，不是代码问题。人越多，某一对设备连不上的可能性越大。

## 注意

- Trystero 版本固定为 0.27.0，升级前请先对照新版接口。
- 4 位房间号只有 1 万种：陌生人同时使用同一个号码会进到同一个房间，房间内容靠房间号加密，不适合保密场景。
- 房主刷新或关掉页面，就算离开；会由下一位接任，游戏重新开始。
